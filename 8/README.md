## Решение

Рассчитаем общее число необходимых ресурсов:
```
vCPU: 1\*3 + 1\*3 + 0,2\*5 + 1\*10 = 17
RAM: 4\*3 + 4\*3 + 0,05\*5 + 0,6\*10 = 30,25 ГБ
```

Итого потребуется 30,25 ГБ и 17 vCPU (17000 m)

Начнем рассчет с варианта с 3 нодами, т.к. требуется 3 копии БД и кэша.

17 / 3 =~ 6 vCPU. Но облачные провайдеры (например, Yandex Cloud) позволяют выбирать vCPU по степени двойки, поэтому ближайшее минимальное - 8 vCPU:
```
6% = 60m +
1% = 10m +
2 * 0,5% = 10m +
4 * 0,25% = 10m
------------------
total      = 90m
```

8000m - 90m = 7910m - сколько ресурсов CPU остается на одной ноде для запуска подов.

3 * 7910m = 23730m - суммарно на всех 3-х нодах.

Но в задании есть требование для отказоустойчивости в случае выхода из строя для одной ноды.

2 * 7910m = 15820m - не хватит (т.к. суммарно для приложения 17000m).

Значит, выделение ресурсов надо организовать так, чтобы одна нода могла полностью распределить свои ресурсы по другим нодам.

Соответственно, необходимо увеличить кол-во vCPU, ближайшая степень двойки - 16 vCPU:
```
6% = 60m +
1% = 10m +
2 * 0,5% = 10m +
12 * 0,25% = 30m
------------------
total      = 110m
```

16000m - 110m = 15890m - сколько ресурсов CPU остается на одной ноде для запуска подов.

3 * 15890m = 47670m - на весь кластер. Этого хватит с головой, но это неэффективный подход - ресурсы будут простаивать, а мы будем переплачивать. 


Нам необходимо суммарно M нод, а (M-1) нод должны функционировать в случае отказа одного из нод.

Мы знаем, что у (M-1) нод должно быть суммарно минимум 30,25 ГБ RAM и 17000m (vCPU). При этом, согласно [статье](https://learnkube.com/kubernetes-node-size), разбивать кластер на микроноды не выгодно с точки зрения эффективного использования ресурсов самими подами.

Если смотреть ограничения на выделение ресурсов vCPU в Yandex Cloud:
vCPU - 2, 4, 8, 16, 32 ...

то логичнее всего брать 4 vCPU, т.к. 4 * 5 = 20 vCPU - это самое минимальное число больше 17, кроме 2 * 9 = 18. Но 2 vCPU мы не будем рассматривать, т.к. это будет [неэффективно](https://learnkube.com/kubernetes-node-size).

Тогда получаем:

4 vCPU:
```
6% = 60m +
1% = 10m +
2 * 0,5% = 10m +
------------------
total      = 80m
```

4000m - 80m = 3920m - сколько ресурсов CPU остается на одной ноде для запуска подов.

5 * 3920m = 19600m - сколько ресурсов в кластере из 5 нод по 4 vCPU каждый. Этого более чем хватает.

Теперь рассчитаем необходимый объем памяти.

30,25 / 5 = 6,05 ГБ - необходимый минимум, но ближайшее разрешенное число у облачных провайдеров - 8 ГБ.


# Ответ
Для поставленной задачи требуется 5+1=6 нодов с ресурсами 4 vCPU и 8 ГБ ОЗУ.
